# The line caps

`just cap` enforces three caps and one audited list. This file is what each one
is for and why every exemption is exempt; `docs/generator.md` is how the
generator is laid out, and `CLAUDE.md` rule 2 is the rule this serves.

| What | Cap | How |
| --- | --- | --- |
| Go | 200 | line count, no exemptions |
| hand-written Markdown | 250 | line count, four exemptions below |
| generated `.proto` | 200 | line count against `line-cap-exemptions.txt` |

The Go cap is tighter than prose on purpose. The generator is decomposed by
stage (`docs/generator.md`), so a file over 200 lines usually means two stages
have merged -- which is the thing that layout exists to prevent. Split it along
the stage boundary rather than compressing it. This document exists because
that rule applied to itself: `docs/generator.md` hit 262 lines when the docs
target landed, and the caps were the section that was about something else.

## The proto cap is enforced by an audited list

`line-cap-exemptions.txt` names the 93 files over 200 lines, and the check runs
**both ways**: an unlisted file over the cap fails, and a listed file back
under the cap fails. The second direction is the one that matters. A list that
only ever grows is a list nobody rereads, and this repository rejects
hand-kept tables everywhere else for exactly that reason; making a *removal*
fail CI too is what keeps this one honest.

Every entry is a single message or a single enum, and that invariant is what
makes the list reviewable -- a new entry is always justified by the same
one-line reason, and a splittable file can never quietly join it. Getting there
took splitting `states.proto`: 80 of them held 415 enums between them, 16 ran
past 200 lines, and one held 19 unrelated enums. One enum per file costs 335
extra files and buys an exemption list containing nothing that could be split.

The 93 are irreducible, and not because of comment volume: strip every comment
from `air_handling_unit.proto` and 6,515 lines remain, 32x over the cap. No
documentation strategy reaches 200 for a 450-field message.

## Markdown and Go exemptions

Exempt, all for the same reason -- the cap's remedy is to split, and splitting
is unavailable or actively makes the document worse:

- `README.md` files under `protobuf/digitalbuildings/` -- generated by
  `cmd/docs`, and a reference page is as long as the resource it documents.
  The qualifier matters: a README under `protobuf/extensions/` would be
  hand-written, and exempting it here on the grounds that it is generated
  would be exempting it on a false premise.
- `README.md` -- the entry document. Its length is diagrams, and a reader who
  must follow a link to see how the thing works has been given a worse README,
  not a shorter one.
- `docs/sample-reference.md` -- a specimen of what the docs generator emits.
  Splitting it would misrepresent what a real page looks like. It is **written
  by `just docs`**, copied verbatim from `FanCoilUnit`'s page, so it cannot
  drift into advertising a layout the generator stopped producing.
- `CLAUDE.md` -- the rule document, and the exemption most worth justifying
  because it is self-serving if left unargued.

  It already splits: rules 10-15 are in `docs/conventions.md`, and four files
  are pulled in by `@`. That is the point. Everything imported by `@` is
  concatenated back into one context, so moving rules 7-9 behind another `@`
  would reduce nothing a reader or an agent actually experiences -- it would
  buy the number with indirection, which is what the cap exists to prevent.

  The residue is genuinely rule text. Coversa-protobuf's equivalent fits in
  250 lines because VSS is one tree with seven domains; this ontology is
  thirteen namespaces, seven facets and 2,637 entity types, and rules 6, 7 and
  8 each have to say more as a result. Deleting that reasoning to hit a line
  count would leave the rules asserted rather than argued.

  What is *not* exempt is duplication: a paragraph here that restates
  `docs/decisions.md` should be a pointer, and several already are.

Everything else is capped, including every other file under `docs/`.

Rule 2 adds a structural rule on top of the line cap: **one message or one
enum per file**. `messages.proto` is the single exception -- a request and its
response are meaningless apart.
